# Звіт про продуктивність генераторного конвеєра

## 1. Мета дослідження

Метою дослідження є порівняння продуктивності двох підходів до обробки великого набору даних: генераторного конвеєра та обробки з використанням проміжних списків.

Для порівняння використано набір із 200 000 рецептів у форматі JSON Lines (JSONL).

## 2. Характеристики комп'ютера

| Параметр | Значення |
|---|---|
| Процесор | Intel Core i5-1245U (12th Gen) |
| Оперативна пам'ять | 15,69 ГіБ |
| Операційна система | Windows |
| Версія Python | 3.14.7 |

## 4. Порівняння продуктивності

Для вимірювання часу виконання використано функцію `time.perf_counter()`, а для визначення пікового споживання пам'яті — модуль `tracemalloc`.

| Метод обробки | Кількість рецептів | Час виконання | Пікова пам'ять |
|---|---:|---:|---:|
| Генераторний конвеєр | 179 800 | 3,02 с | 45,9 МБ |
| Проміжні списки | 179 800 | 3,39 с | 195,6 МБ |

Генераторний конвеєр використав приблизно у 4,26 раза менше оперативної пам'яті та виконав обробку приблизно на 11% швидше за підхід із проміжними списками.

## 5. Перевірка лінивої обробки

Для перевірки використано команду:

`recipe-aggregator data/large.jsonl --preview 5`

У результаті програма вивела п'ять коректних унікальних рецептів, прочитавши лише 7 рядків із 200 000.

Один запис було відхилено через порожню назву, а ще один — як дублікат.

Це підтверджує, що генераторний конвеєр обробляє дані поступово, не завантажуючи весь файл у пам'ять.

## 6. Аналіз споживання пам'яті

Генераторний конвеєр використовує оператор `yield` для послідовної передачі записів між етапами обробки.

Основним джерелом залишкового споживання пам'яті є множина `seen`, яка містить ключі вже оброблених рецептів для виявлення дублікатів.

На відміну від спискового підходу, генераторний конвеєр не створює проміжні списки всіх записів, завдяки чому використання пам'яті значно зменшується.

## 7. Висновок

У ході практичної роботи реалізовано генераторний конвеєр для обробки великого набору рецептів. Забезпечено перевірку коректності записів, видалення дублікатів, обчислення статистики за один прохід і пакетну обробку даних.

За допомогою функцій `itertools.islice()` та `itertools.batched()` реалізовано попередній перегляд і розбиття потоку на пакети.

Порівняльні вимірювання показали, що генераторний підхід є ефективнішим за використання проміжних списків за споживанням оперативної пам'яті, а в проведеному тесті також забезпечив менший час виконання.
