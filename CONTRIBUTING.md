# CONTRIBUTING.md

## Іменування гілок

Для кожної окремої задачі створюється власна гілка від актуальної гілки `main`.

Використовуються такі префікси:

- `feature/` — додавання нової функціональності;
- `fix/` — виправлення помилок;
- `refactor/` — зміна структури коду без зміни його поведінки;
- `docs/` — зміни документації;
- `chore/` — службові зміни та конфігурація.

Приклади:

`feature/title-normalizer`

`fix/empty-title`

`docs/update-readme`

## Формат повідомлень комітів

Коміт повинен містити одну логічно завершену зміну.

Рекомендований формат:

`type: короткий опис зміни`

Основні типи:

- `feat` — нова функціональність;
- `fix` — виправлення помилки;
- `test` — додавання або зміна тестів;
- `docs` — зміни документації;
- `refactor` — рефакторинг коду;
- `chore` — службові зміни.

Приклади:

`feat: add recipe title normalizer`

`test: cover whitespace-only title`

`docs: update contributing guidelines`

## Вимоги до Pull Request

Перед створенням Pull Request необхідно:

- переконатися, що зміни виконані в окремій гілці;
- перевірити, що коміти є атомарними та мають зрозумілі повідомлення;
- виконати `python -m ruff check .`;
- виконати `python -m ruff format --check .`;
- виконати `python -m pytest -q`;
- переконатися, що в зміни не потрапили `.env`, `.venv`, кеші або інші тимчасові файли;
- описати, що було зроблено, навіщо це потрібно та як перевірити результат;
- отримати щонайменше одне схвалення рецензента перед злиттям у `main`.
