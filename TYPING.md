# Типізація проєкту Recipe Aggregator

## 1. Мета роботи

Забезпечити сувору типізацію модулів застосунку Recipe Aggregator за допомогою mypy, реалізувати перевірку інваріантів доменної моделі та валідацію вхідних даних засобами Pydantic.

## 2. Початкова перевірка

Команда: `python -m mypy src`

Результат: `Success: no issues found in 8 source files`.

Початкова перевірка без режиму strict не виявила помилок.

Під час першого запуску `python -m mypy --strict src tests` виявлено **20 помилок у 6 файлах** (перевірено 17 файлів).

Основні причини: відсутні анотації типів, використання нетипізованого `dict` та несумісність типів колекцій.

## 3. Виконані зміни

- До доменної моделі `Recipe` додано перевірки інваріантів у `__post_init__()`.
- Реалізовано модель `RecipeIn` на основі Pydantic.
- Додано валідацію даних у конвеєрі з підрахунком відхилених записів.
- Уточнено типи функцій читання JSON та JSONL.
- Додано анотації типів функцій і тестів.
- Створено типізовану конфігурацію `Settings`.
- Налаштовано перевірки Ruff, mypy та pytest.

## 4. Використання Any

У власних анотаціях типів замість `Any` використано конкретні типи та `object`.

На межі читання JSON застосовується `json.loads()`, результат якого може мати невизначену структуру. Отримане значення передається через змінну типу `object` та перевіряється перед використанням.

Для перевірки записів рецептів застосовується Pydantic.

## 5. Підсумкова перевірка

Команда: `python -m mypy --strict src tests`

Результат: `Success: no issues found in 18 source files`.

**Підсумкова кількість помилок mypy: 0.**

Додаткові перевірки:

- `python -m pytest -q` — 31 тест пройдено.
- `python -m ruff check .` — перевірка успішна.

## 6. Висновок

У результаті роботи забезпечено сувору статичну типізацію модулів проєкту, перевірку інваріантів доменної моделі та валідацію зовнішніх даних. Усі перевірені модулі успішно проходять mypy у режимі strict.
